# Strategy for handling upstream changes

 - Pull from upstream/main into your local main branch regularly
 - Regularly rebase your branch onto the latest `main`
 - Never write feature code directly on your local main branch. 
   Always branch out (git checkout -b feature/...) so your main 
   remains a pristine reflection of the upstream source
 - Сlean up history before a pull request

# Best practices for commit messages

 - Use a clear structure (type: short summary):
 "chore: initial commit"
 "feat: add JWT-based user authentication"
 "refactor: split JWT authentication into access and refresh tokens"
 "fix: implement token validation function"

 - Keep the imperative mood: 
 Write descriptions as commands ("add function" 
 instead of "added function" or "-ing function").
